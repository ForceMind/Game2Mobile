# S2Arm 借鉴与整合执行计划

状态：执行中；无资源工具与运行时防护集中交付见 [本轮记录](ASSET_FREE_CLOSEOUT.zh-CN.md)。更新日期：2026-11-10（America/Los_Angeles）。

本计划将已完成的源码研究转换为可提交、可验收的工作包。第一交付目标是 Nintendo Switch《Diablo II: Resurrected》`3.3.94012` 在 Game2Mobile 中完成独立构建、安装和实际游玩验证。主目标为 iOS 26 / Metal 4，保留 iOS 18 / Metal 3 兼容路径；macOS 用于宿主验证及产品构建。具体源码映射见 [差分清单](S2ARM_DIFFERENCES.zh-CN.md)。

## 1. 固定基线与采用原则

| 项目 | 固定版本 | 本计划如何使用 |

| Game2Mobile 原始来源 | `jhaizhou-ops/d2r-mobile`，`685d3ddef8bf75768fd4c51228566f2e8d2a5182` | 共同来源说明，不能把同源已有功能当成本次新增 |
| S2Arm 已审阅源码 | `cf1f19c5c9d80abf78b1296cb8d436a4deab3978` | 差分表、源码链接及候选实现的研究基线 |
| S2Arm 后续观察 | `779bcf69c639c8680fabad6d0d97903720bbe8ab` | 2026-11-09 重新查询到的主线；尚未完成相对于研究基线的逐项复审，不直接采用 |

Game2Mobile 已有 x18 / TLS / SVC 静态改写、独占指令窗口处理、模块重定位、签名代码节映射、NVN→Metal、着色器翻译与资源校验。整合采取“确定差异 → 证明需要 → 最小改动 → 回归”的顺序。新启动器、更大的服务层或改写器语言变化本身不构成替换现有内核的依据。[来源与现状][g2-status]、[现有图形链][g2-gfx]、[现有改写验证][g2-verify]。

S2Arm 的通用化实现作为平行对照。每项候选必须记录来源 SHA、对应文件、适用游戏构建号、实际改变的语义及撤回方式；不得把上游历史帧率、短时普查或其他游戏的结果登记为 Game2Mobile 实测。

## 2. 工作包与验收

`source_reviewed` 只表示源码事实已核对；`implemented_tests` 表示已实现且无游戏资源测试已通过，Apple CI 结果按对应提交追踪，真实输入与设备尚未验证； `partial_implementation` 表示仅交付独立的部分接口、尚未达到整项验收；`planned` 表示尚未进入；`needs_private_run` 表示必须由受控 Apple 环境和合法输入完成。任何状态都不能代替对应范围之外的构建或设备证据。

| 编号 | 优先级 / 状态 | 工作与依赖 | 完成条件 |
|---|---|---|---|
| S2-01 | P0 / source_reviewed | 固定双方版本，建立改写、加载、服务、图形、交付接口差分 | 每项有固定源码链接、已有能力、候选变化和待验证问题；更新上游时先更新差分 |
| S2-02 | P0 / implemented_tests | 原生启动阶段事件与只读日志分析；依赖 S2-01 | 同一运行可串联宿主、装载、SDK、入口、GPU 提交与首帧观察；并发记录不破坏行或序号；合成日志证明不会混入旧局或误把 DONE 当可玩 |
| S2-03 | P0 / implemented_tests | 构建输入、游戏版本和运行产物的身份核验；复用既有缓存 / shader / bundle 检查 | 正常匹配可解释；缺少、过期或冲突证据明确拒绝或报告未知；不伪造无法提取的游戏身份；单独输出核验范围 |
| S2-04 | P0 / partial_implementation | 按实际差异补改写与 loader 边界；依赖 S2-01，真实故障结合 S2-02 | 合成指令/模块反例通过；真实 D2R 模块结构与语义对照通过后才启用相关改动；没有证据支持的改动不混入默认路径 |
| S2-05 | P0 / needs_private_run | 完成 M1 真实资源生成、完整链接、签名、安装与启动；依赖 S2-02/03 | 依 [M1 私有构建流程](M1_PRIVATE_BUILD.zh-CN.md) 留存同次构建证据；进入主菜单与可操作场景；核触控/手柄、画面、声音、存档恢复；不以首帧代替游玩 |
| S2-06 | P1 / partial_implementation | Metal 3/4 对照、纹理脏页与资源生命周期；根据 S2-05 的故障排序 | 相同输入和场景对照两个配置；覆盖内存池替换、CPU 写入、追踪失败、GPU 同步；结果按设备/系统登记 |
| S2-07 | P1 / planned | 单帧录放和逐绘制定位；依赖可采集的真实帧 | 固定私有帧可重复回放；记录 shader 链与宿主布局；对未覆盖的深度/多采样等资源明确报告，不承诺逐像素完全复现 |
| S2-08 | P1 / partial_implementation | 统一构建任务、错误码、诊断包及图形操作流程 | 界面与现有脚本共用状态；取消/中断/失败不发布半成品；按包内宿主版本提示重建；诊断包有可审查的内容清单 |
| S2-09 | P1 / partial_implementation | AI 控制入口；优先状态、诊断、下一步、日志，再接构建 | JSON 结果稳定、退出码明确；AI 与界面操作同一任务；本机控制端点限定访问并校验凭据；未实现动作明确返回不支持 |
| S2-10 | P1 / partial_implementation | 兼容性卡与持续运行验收；依赖 S2-05 | 支持/启用/验证分别记录；证据绑定游戏、宿主、shader、设备、系统；新增质量目标为连续游玩 30 分钟及退出后存档恢复，不能替代原 M1 清单 |
| S2-11 | P2 / planned | 提炼 D2R 适配包，之后接入第二款游戏 | 版本识别、特定补丁、shader facts、触控布局与验收场景有独立归属；公共层无需散落新增游戏地址判断 |
| S2-12 | P2 / planned | 共用应用壳、多游戏库、动态模块与其他平台 | 先按具体第二款游戏的需求接入；代码签名、内存模型、后端能力逐平台验收；Android/HarmonyOS 目录或接口存在不算可用版本 |

S2-02/03 的主实现已通过 PR #15 合入，后续原生内存池修复见 #17/#19。本次 #20 继续完成 Loader 布局/动态/符号/重定位/门的边界防护，内存保护失败路径，M1 进程组超时与取消清理、仓库互斥锁、异常终态、受限普通文件读取、仅摘要诊断包以及显式本机构建入口。S2-10 的本机验收记录工具已实现：核对真实 App 字节、同次日志、身份、附件和人工填写项目，但只输出记录一致性，不证明设备真实性。

S2-04/06 仍需目标游戏与 GPU 输出验证；S2-07 完整帧录放器未交付，依赖真实私有帧。S2-08 已提供独立 SwiftUI macOS 工程操作器（`dm/launcher/MacOperator`），继续增加不访问私有资源的构建工具链 Doctor 及本地未公证 DMG 打包：只读启动/构建状态、公开工具完整性和阶段计划与显式确认本机构建，复用同一 Python 执行器；并非真实游戏图形启动器、远程 HTTP 控制服务、可恢复任务队列或设备安装器，App 交互和真实游戏构建仍需本机验收。S2-11/12 保持原先首款验收后扩展的顺序，不能把目录或接口计为第二款游戏可用。详细实现、命令和未完成范围见 [工程交付与接续边界](ASSET_FREE_CLOSEOUT.zh-CN.md)。

## 3. 本轮实现范围与接口约束

本轮已实现 S2-02、S2-03 的可独立验证部分，并通过无游戏资源测试；S2-01 的审阅结果已记录。Apple CI 结果由各 PR 的对应提交记录核对；真实游戏输入、完整游戏 App 构建和设备验证尚未完成。协议、使用命令和输出边界见 [启动诊断与构建身份核验](STARTUP_DIAGNOSTICS.zh-CN.md)。下列条目记录已实现的接口及继续适用的验收约束，后续证据由对应 PR 的测试和 CI 记录更新。

### 3.1 启动事件与日志分析

已实现事件前缀 `G2M_BOOT `，后接一行 JSON。事件包含格式版本、运行标识、递增序号、单调相对时间、阶段和结果。阶段区分宿主开始、模块加载、重定位、SDK 初始化、模块初始化、游戏入口、GPU 首次提交、首帧观察和宿主返回。

- 运行标识可与现有 `DM_RUN_RECEIPT` 关联；普通图标启动也应生成本次进程标识。
- GPU 提交与首帧必须在对应真实观察点记录，不能把调用显示接口等同屏幕已呈现。
- GPU 热路径只记录首次事件；不得每帧读环境变量或打印大日志。
- 线程并发必须得到完整、可排序的记录；不能在信号处理器里引入锁和 stdio。
- 只读分析器按运行标识选择一局，区分格式损坏、阶段未完成、明确错误和首帧已观察。
- 缺记录表示证据不足；日志不证明黑屏的唯一根因，也不证明画面正确、存档可靠或游戏可玩。
- `DONE`、旧局首帧和其他运行的成功记录均不能补足当前运行。

### 3.2 身份检查

已实现 `scripts/build_identity.py`，将源码提交及状态、产品版本、构建配置、模块 Build ID 记录与摘要、运行表和 shader 缓存指纹绑定到本次清单，并校验最终 `DmIOS` 可执行文件内嵌的游戏节。来源无法可靠取得时明确拒绝或报告未知；不得用当前源码推算的版本冒充历史 App 中实际存在的版本。

复用 `product.sh` 的完整改写回执、`m1_shader_inventory.py` 的映射/库/反射检查和 `m1_game_bundle.py` 的真实游戏包检查。新身份工具只增强来源关联，不降低已有着色器完整性、完整链接与签名检查要求。手写 JSON、未签名夹具或文件名相同均不构成真实游戏身份和安装证据。[现有构建流程][g2-m1]。

### 3.3 独立审查与剩余证据

身份脚本的独立审查发现了未跟踪源码遗漏、深层损坏 JSON 的错误处理、完整映像摘要未核验，以及 Xcode 排除 `.DS_Store` 导致缓存指纹误差四项问题，均已修复并通过无资源回归。Apple 链接匿名节薄可执行文件与新 Mach-O 解析器的集成检查已在 #15 的对应 CI 通过；该检查使用公开夹具，不构成真实游戏完整链接、签名安装或游玩证据。

## 4. 哪些工作可在当前环境验收

| 环境 | 可以证明 | 无法据此证明 |
|---|---|---|
| Linux，无游戏资源 | 源码差分、标准 C 事件记录、并发/格式测试、只读分析器、合成身份反例、脚本失败传播 | Apple API 链接、真实 NSO 语义、签名、设备启动、Metal 输出 |
| Apple CI，无游戏资源 | iOS 26 / iOS 18 源码编译、无资源项目生成、公开夹具和宿主自测 | 完整游戏 App 链接、真实资源生成、安装与游玩 |
| 受控 Apple Silicon Mac，合法版本匹配的 ExeFS/RomFS | 真正模块改写、资源生成、shader 翻译、完整链接及本地签名检查 | 未连接设备的安装、触控、声音、实际帧率或存档恢复 |
| 指定 iPhone/iPad，匹配签名与资源 | 安装、主菜单、场景交互、图形/音频、存档、持续运行、热态性能 | 未测试设备、其他系统、其他游戏构建或其他宿主版本的兼容性 |

不会为了通过公开 CI 构造商业资源的替代头文件并宣称真实完整构建。游戏原件、派生资源、完整帧录制、签名凭据和含私有路径的原始运行日志均留在受控环境；公开仓库只记录允许公开的源码、合成夹具、脱敏结果与范围。

## 5. 每次采用的提交与回归规则

1. 固定候选源码版本，先检查上游变更及许可归属，再写明要解决的具体问题。
2. 原创实现与直接移入代码分别登记；不因双方同源就删除原版权或许可。
3. 每个 PR 只改变可单独验证的一组行为，包含对应反例、失败路径和最小回归。
4. 合成测试、Apple 编译、签名安装、首帧和游玩分别记录；失败和未测均保留。
5. 新增编译单元时更新实际源清单与相关断言；历史编译报告保持其原版本范围。
6. 设备对照记录游戏 Build ID、宿主 SHA、shader 链/产物身份、设备、系统、配置、测试日期及运行标识。
7. 没有完成 M1 的真实输入与设备验收，不关闭 M1、不发布可玩版结论。
